# HeatSupplyCalculator

Настольная программа (Java + Swing) для расчёта теплопритоков в помещениях здания, например коттеджа:
по каждому помещению отдельно и по зданию в целом. Результат выводится в ваттах и киловаттах.

При расчёте учитываются:

- солнечная радиация через окна;
- люди;
- бытовая и производственная техника;
- приточная вентиляция;
- кровля.

## Возможности

- Список помещений: создание, редактирование, удаление. Номер помещения должен быть уникальным.
- Редактор помещения с четырьмя вкладками: **Окна**, **Люди**, **Оборудование**, **Вентиляция и кровля**.
- Расчёт по одному помещению прямо в редакторе и по всем помещениям сразу — кнопкой «Рассчитать» в главном окне.
- Итог по зданию в Вт и кВт. Если помещение рассчитать не удалось (например, не заданы окна), программа показывает причину и считает итог по остальным.
- Проверка ввода: размеры окон и площадь кровли не могут быть отрицательными, наименование обязательно.
- Сборка в exe со встроенной JRE (jpackage).

> Данные хранятся только в памяти: сохранения в файл нет, после закрытия программы список помещений теряется.

## Требования

- JDK 25. В `Main` используется `static void main()` без аргументов, на более старых версиях Java такая запись не запустится.
- Gradle ставить не нужно: используется обёртка `gradlew` (Gradle 9.2).

## Запуск

```bash
./gradlew run
```

Для Windows: `gradlew.bat run`.

## Сборка exe-приложения

```bash
./gradlew packageExe
```

Результат появится в `build/jpackage`: папка с `HeatSupplyCalculator.exe` и встроенной JRE, устанавливать Java на целевой машине не нужно.

Параметры:

| Параметр | Описание |
|---|---|
| `-PpackageType=exe` или `msi` | Собрать установщик вместо папки (`app-image` по умолчанию). Для установщика на Windows нужен WiX Toolset |
| `-Pconsole=true` | Запускать вместе с консольным окном (удобно для отладки) |

Пример: `./gradlew packageExe -Pconsole=true`.

## Как считается теплоприток

Итог по помещению — сумма пяти слагаемых:

```
Q = Q(окна) + Q(люди) + Q(техника) + Q(вентиляция) + Q(кровля)
```

### Окна

Теплопоступление одного окна: `площадь × удельная нагрузка стороны света`.

- Если установлена анти-УФ плёнка, результат умножается на 0.5.
- Если окно затенено, вместо нагрузки стороны света берётся значение «теплопоступление в тени, Вт/м²», заданное пользователем.

Удельная нагрузка по сторонам света:

| Сторона | Вт/м² | Сторона | Вт/м² |
|---|---|---|---|
| Север | 100 | Юг | 230 |
| Северо-восток | 180 | Юго-запад | 310 |
| Восток | 200 | Запад | 290 |
| Юго-восток | 240 | Северо-запад | 200 |

В помещении выбирается самая «жаркая» сторона, то есть сторона с наибольшей нагрузкой среди его окон.
Окна учитываются с коэффициентами:

| Положение окна относительно самой жаркой стороны | Коэффициент |
|---|---|
| На самой жаркой стороне | 1.0 |
| На смежной стороне (в пределах 90°) | 0.5 |
| На противолежащей стороне | 0.3 |

Пример: окна на юго-западе (310), юге (230) и северо-востоке (180), по 1 м² каждое.
Самая жаркая сторона — юго-запад: `310 + 230 × 0.5 + 180 × 0.3 = 479 Вт`.

### Люди

Тепловыделение одного человека зависит от вида деятельности и температуры в помещении (22 или 25 °C), Вт:

| Вид деятельности | 22 °C | 25 °C |
|---|---|---|
| Покой | 105 | 93 |
| Лёгкая I | 148 | 145 |
| Средняя IIа | 196 | 194 |
| Средняя IIб | 244 | 242 |
| Тяжёлая | 292 | 291 |

### Оборудование

| Тип | Вт |
|---|---|
| ПК | 300 |
| Ноутбук | 100 |
| Холодильник | 100 |
| Телевизор | 50 |
| Принтер | 100 |

Для другой техники можно указать тепловыделение вручную.

### Приточная вентиляция

```
Q = 0.5 × L × (35 − t)
```

где `L` — расход воздуха, м³/ч, `t` — температура в помещении, °C.

### Кровля

```
Q = 10 × S
```

где `S` — площадь кровли, м².

## Тесты

В проекте 68 автотестов на JUnit 5: расчётное ядро (`logicCore`) и модель помещения из интерфейса (`RoomSpec`).
Интерфейс на Swing автотестами не покрыт.

```bash
./gradlew test
```

Отчёт о покрытии (JaCoCo) после запуска: `build/reports/jacoco/test/html/index.html`.

Тесты на известные дефекты помечены `@Disabled("BUG-N: ...")`. Они описывают правильное поведение
и сейчас упали бы; после исправления кода достаточно убрать `@Disabled`.

## Известные проблемы

| № | Проблема |
|---|---|
| BUG-1 | `Room` запоминает самую жаркую сторону и не пересчитывает её, если после первого расчёта изменить список окон |
| BUG-2 | Конструктор `Room` принимает `null` для вентиляции и кровли, но `calculateSupply()` падает с `NullPointerException` (интерфейс обходит это нулевыми значениями) |
| BUG-3 | Для температуры, отличной от 22 и 25 °C, тепловыделение человека молча равно 0 |
| BUG-5 | В расчётном ядре нет проверки отрицательных значений (площадь окна, кровли, мощность техники) |

Для помещения без окон, людей или техники расчёт завершается ошибкой «пустой список …» — это текущее поведение.

## Структура проекта

```
src/main/java/ru/ASTiNEZh
├── Main.java                  # точка входа
├── UI/                        # интерфейс на Swing
│   ├── MainFrame.java         # главное окно: список помещений, общий итог
│   ├── dialogs/               # редакторы помещения, окон, людей, оборудования
│   ├── common/                # общие компоненты, подписи, утилиты
│   └── model/RoomSpec.java    # описание помещения, вводимое пользователем
└── logicCore/                 # расчётное ядро без зависимостей от интерфейса
    ├── room/Room.java         # суммарный теплоприток помещения
    └── supplyers/             # источники тепла: окна, люди, техника, вентиляция, кровля
```
